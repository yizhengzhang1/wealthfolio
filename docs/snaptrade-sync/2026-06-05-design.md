# snaptrade-sync 设计文档

日期：2026-06-05 · 状态：待评审 · 作者：与 Claude 协作

## 1. 目标与范围

把 **Charles Schwab（嘉信）** 的持仓与已实现盈亏，用**用户自己的免费 SnapTrade 开发者 key** 拉取，写进自托管的 wealthfolio。形态**复刻 `tools/ibkr-sync`**：HOLDINGS 快照 + 已实现盈亏台账，喂 `/snapshots/import`。嘉信与 IBKR 在 wealthfolio 里行为一致、共用自建 `/realized` 页。

**范围内**：嘉信账户的持仓（含期权）、现金、已实现盈亏。
**范围外（YAGNI）**：不接 Wealthfolio Connect 付费托管；不改动 IBKR 同步；不做 Greeks；不提前抽象"通用多券商框架"（先把嘉信跑通，公共层等真有第二家券商再抽）。

## 2. 背景与决策

- 数据源选定 **SnapTrade**，用用户自己的免费 key（免费层：1 用户 / 5 连接 / 实时持仓数据），**不走** Wealthfolio Connect（$8/mo 托管层，底层同为 SnapTrade）。
- 模式选 **HOLDINGS 快照 + realized 台账**（非 wealthfolio 原生 TRANSACTIONS 流水）。理由：与 IBKR 体系一致、共用 `/realized` 页、快照以券商当前持仓为准（不依赖流水回放，规避 SnapTrade 嘉信流水只回看到 2/20 的重建隐患）。
- 决策对比见 ws 目录 `方案对比-自维护vsConnect.html`。

## 3. 与 ibkr-sync 的关系（复用矩阵）

| 模块 | 复用度 | 策略 |
|---|---|---|
| `wealthfolio.ts` | 100% | 原样复制（HTTP 客户端与券商无关）。建议先复制，第二家券商出现时再抽公共包。 |
| `state.ts` | ~95% | 复制；把 trade 类型从 `IbkrTrade` 换成 `SnaptradeActivity`、调整 asset key；reconcile / grace window / 台账去重逻辑不变。 |
| `sync.ts` | ~60% | 沿用 16 步编排骨架；第 1 步改为"调 SnapTrade SDK 取数"（不再读 `/tmp/*.json`）。 |
| `mapping.ts` | ~40% | 复用 `stampRealizedGain`、`positionAssetKey`；**重写**期权解析（SnapTrade 直接给结构化 `option_symbol`，比 IBKR 解析 `contract_description` 括号**更简单**）。 |
| `ibkr.ts` → `snaptrade.ts` | 0% | 重写：SnapTrade SDK 封装 + Zod schema。 |
| `scripts/` | 部分 | `install-cron.sh` 复制；`run-*.sh` **大幅简化**（无 `claude -p`，直接 `npx tsx`）；**无** `routine-prompt.txt`。 |

**关键架构差异**：ibkr-sync 靠 headless `claude -p` 会话调 IBKR MCP 取数（因 IBKR 当时只能经 MCP）。snaptrade-sync 用 **SnapTrade 官方 TS SDK** 直接取数，`sync.ts` 自己完成 fetch→transform→POST，**去掉了 Claude/MCP 依赖层**，更简单、更稳。

## 5. 数据源契约（SnapTrade，已实测 2026-06-05）

**认证**：`new Snaptrade({clientId, consumerKey})` + 持久化的 `userId`/`userSecret`（首次 `registerSnapTradeUser` 得到，userSecret 不可找回，存 secrets.local）。

**持仓** `accountInformation.getUserHoldings({userId, userSecret, accountId})` →
- `positions[]`（股票）：`symbol.symbol`、`symbol.exchange.mic_code`、`units`(带符号)、`price`、`average_purchase_price`
- `option_positions[]`（期权）：`symbol.option_symbol.{ticker(OCC), strike_price, expiration_date, option_type(CALL/PUT), is_mini_option, underlying_symbol.symbol}`、`units`(带符号=多空)、`price`(每股现价)、`average_purchase_price`(每股均价)
- `balances[]`：`{currency.code, cash, buying_power}`

**流水** `accountInformation.getAccountActivities({userId, userSecret, accountId, offset/limit})` →
- 每条：`type`(BUY/SELL/OPTIONEXPIRATION/…)、`option_type`(腿类型 BUY_TO_OPEN/SELL_TO_CLOSE/…)、`symbol` 或 `option_symbol`、`amount`(带符号现金)、`price`、`units`(带符号)、`fee`、`currency.code`、`trade_date`、`settlement_date`、`external_reference_id`(幂等键)
- **分页**：单页上限 ~1000 行，必须翻页取全（嘉信实测最早到 2026-02-20）。
- ⚠️ **无 `realized_pnl` 字段** → 已实现盈亏须自算（见 §8）。

**更新频率**：免费层持仓"实时"（每次请求即时）；流水缓存、每天 1 次、延迟约 1 天。

## 6. 映射规则

**期权持仓 → HoldingsPositionInput + 资产预创建**
- 乘数 `multiplier = is_mini_option ? 10 : 100`（指数期权如 SPXW 也是 100）。
- 先 `POST /assets`：`{kind:"INVESTMENT", quoteMode:"MANUAL", quoteCcy:"USD", instrumentType:"OPTION", instrumentSymbol:OCC, displayCode:OCC, metadata:{option:{underlyingAssetId:underlying, expiration, right, strike, multiplier:String(100|10), occSymbol:OCC}}}` → 拿 `assetId`。
- 持仓行：`{assetId, symbol:OCC, quantity:String(units), avgCost:String(average_purchase_price), currency:"USD", instrumentType:"OPTION"}`。
- 报价覆盖：`POST /market-data/quotes/import`，`{symbol:assetId, date, close:price, currency}`，`overwriteExisting:true`。

**股票持仓 → HoldingsPositionInput**：`{symbol:ticker, quantity:String(units), avgCost:String(average_purchase_price), currency:"USD", instrumentType:"EQUITY", exchangeMic:mic_code}`。

**现金**：`balances` → `cashBalances{ "USD": String(cash) }`。

`units` 带符号天然表多空，直接用。

## 7. wealthfolio 写入契约（已查实）

- **账户**：`findOrCreateAccount({name:"Schwab", accountType:"SECURITIES", currency:"USD", provider:"SNAPTRADE", providerAccountId:"SCHWAB-<snaptrade account id 或固定别名>", trackingMode:"HOLDINGS", isActive:true})`。按 `providerAccountId` 去重，与 IBKR 账户并列。
- **快照**：`POST /api/v1/snapshots/import` body `{accountId, snapshots:[{date:"YYYY-MM-DD", positions:[HoldingsPositionInput…], cashBalances:{CCY:amount}, realized:[RealizedEntryInput…]?}]}`。幂等于 `(accountId, date, content)`。
  - `RealizedEntryInput = {underlying, currency, realizedLocal:number}`（Phase 2 才填）。
  - `HoldingsPositionInput.realizedGain`（单标的累计，Phase 2 stamp）。
- **乘数补丁**：fork 已在 `manual_snapshot_service.rs` 把 `contract_multiplier` 改为 `asset.contract_multiplier()`（期权→100，否则→1），对**所有走快照导入**自动生效 → snaptrade-sync 期权成本基础天然正确。
- **已实现盈亏读取闭环**：snapshot 的 `realized[]` 存到 `realized_pnl:{accountId}` KV；前端 `/realized` 走 `GET /api/v1/realized-pnl` 聚合（按 underlying+currency，FX 缺失优雅降级）。`realized:None` 不覆盖、`Some([])` 清零、`Some([...])` 覆盖。

## 8. 已实现盈亏引擎（Phase 2，净新增）

SnapTrade 不给 `realized_pnl`，需自建。方案：**均价（average-cost）回放**。
- 拉全量 `getAccountActivities`（分页），按 `trade_date` 升序，按资产（期权按 OCC 合约、股票按 symbol）维护 `{qty, avgCost}`。
- 开仓（同向增仓）：更新加权均价。平仓/减仓（反向）：`realized += (平仓价 − avgCost) × 平仓数量 × multiplier − 对应 fee`；空头对称处理。
- `OPTIONEXPIRATION`：到期方实现 = 持有成本的全额了结（按 multiplier）。
- 按 `underlying`（期权剥离到标的）+ `currency` 汇总 → `RealizedEntryInput[]`，喂进快照 `realized`。
- 用 `external_reference_id` 做幂等/去重（对齐 state.ts 台账的 `seenTradeIds`）。
- 与 ibkr-sync 的区别：ibkr 是"求和券商给的 realized_pnl"，这里是"自己算 realized_pnl"。state.ts 的台账容器与 grace window 仍复用。

## 9. sync.ts 编排（沿用 ibkr-sync 16 步，关键改动标注）

1. 解析 CLI/env（`--account-name="Schwab"`、`--provider-account-id`、`SNAPTRADE_*`、`WEALTHFOLIO_*`、grace days）。
2. **【改】取数**：SnapTrade SDK → `getUserHoldings`（positions+option_positions+balances）+（Phase 2）`getAccountActivities` 分页全量。
3. reconcile 持仓 vs 上次 state（grace window，复用）。
4. （Phase 2）`realized.ts` 算已实现盈亏台账。
5. 映射 live 持仓 → HoldingsPositionInput（股票/期权）。
6. grace 再注入行（EXPIRED 保 avgCost / CLOSED 置 0）。
7. 现金 → cashBalances。
8. dry-run 分支：打印不 POST。
9. `findOrCreateAccount`（Schwab / HOLDINGS）。
10–12. 预创建期权资产、绑定 assetId 到持仓行。
13. `POST /snapshots/import`（positions + cash +（Phase 2）realized）。
14. `POST /market-data/quotes/import`（期权现价覆盖）。
15. `saveState`。
16. 打印单行 summary，返回 0/1。

## 10. 状态与 grace window

复用 `state.ts`：`live`/`closing`/`realized` 三段，按资产 key 跟踪；持仓从 holdings 消失 → 进 grace window（默认 1 天）→ 过期/平仓区分。台账 `seenTradeIds` 用 `external_reference_id`。`version` 升新号、加 v(ibkr)→v(snaptrade) 迁移或独立文件。

## 11. 配置 / secrets / cron

- `docs/snaptrade-sync/secrets.local.md`（gitignored）：SnapTrade `clientId`/`consumerKey`/`userId`/`userSecret` + wealthfolio URL/password。**建议测试完在 SnapTrade dashboard 轮换一次 consumerKey**（曾贴入聊天）。
- `run-snaptrade.sh`：设最小 PATH + nvm node + `SNAPTRADE_*`/`WEALTHFOLIO_*` env，`cd tools/snaptrade-sync && npx tsx src/sync.ts …`，输出进 `logs/sync-YYYYMMDD.log`。**无 claude -p**。
- `install-cron.sh`：复制，tag `managed-by:snaptrade-sync`，节奏可同 IBKR（如 `0 10,12,22 * * *`，但流水天级更新，频率高也无更多增量）。
- 依赖 `:8088` wealthfolio 容器在跑（同 ibkr-sync）。

## 12. 分期

- **Phase 1（MVP）**：持仓快照（股票+期权+现金），账户/资产/快照/报价四段。嘉信当前持仓在 wealthfolio 正确显示（乘数对）。/realized 暂只有 IBKR。
- **Phase 2**：`realized.ts` 均价回放引擎 → 嘉信已实现盈亏进同一 /realized 页。
- **Phase 3（可选）**：把 wealthfolio.ts/state.ts 抽公共包，支持第三家券商。

## 13. 测试策略

vitest；fixtures 用本次实测真实数据（24 期权持仓 + 活动样本，含 BUY_TO_OPEN/OPTIONEXPIRATION/空头）。重点：期权映射（乘数 100/mini 10、空头负 units）、realized 引擎（开平配对、期权到期、空头、fee）、reconcile/grace、wealthfolio 客户端重试/幂等。

## 14. 风险与未决

- **realized 引擎正确性**：期权多空/到期/被指派/部分平仓的边界，需充分单测；均价 vs FIFO 方法定调（建议均价，和持仓 average_purchase_price 一致）。
- **历史窗口**：SnapTrade 嘉信流水仅回看到 2/20；更早开仓的已实现盈亏无法回算（持仓快照不受影响，成本基础以券商均价为准）。
- **分页**：getAccountActivities 必须翻页，注意上限与增量（按 trade_date 增量拉）。
- **指数期权**：SPXW "dummy underlying re-mapped from SPX"，OCC 在，乘数 100，注意 underlying 解析。
- **免费层条款**：1 用户/5 连接；userSecret 不可找回；consumerKey 轮换。
- **account 别名**：providerAccountId 用 SnapTrade account id（稳定）还是固定别名"SCHWAB-MAIN"，二次确认。

## 15. 验收

- Phase 1：嘉信账户在 wealthfolio 显示 13 股 + 24 期权 + 现金，期权市值含 ×100 乘数正确；与 IBKR 账户并列。
- Phase 2：/realized 页同时含 IBKR 与嘉信，按标的合并、币种正确、缺汇率优雅降级。
- 幂等：重复跑同一天不产生重复/漂移。
